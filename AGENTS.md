# AGENTS.md

Guidance for AI coding agents working in this repository.

## Project overview

`apitube/news-api` — the official PHP SDK for the [APITube News API](https://docs.apitube.io/).
It wraps the REST API (articles, headlines, stories, NLP analysis, reference data,
account balance) behind a typed `Client`. PHP `^8.1`, PSR-4, MIT licensed.

## Setup

```bash
composer install
```

The SDK does not bundle an HTTP client. It relies on PSR-18/PSR-17 auto-discovery
(`php-http/discovery`); `guzzlehttp/guzzle` is installed as a dev dependency so the
test suite and examples have a concrete implementation.

## Build / test

There is no build step (pure PHP, autoloaded via Composer).

```bash
vendor/bin/phpunit                      # run the full suite (config: phpunit.xml)
vendor/bin/phpunit --filter ClientTest  # run a single test class
```

Tests use `php-http/mock-client` to stub HTTP responses — no network calls.

There is **no linter or formatter configured** in this repo (no Pint/PHP-CS-Fixer/PHPStan).
Do not invent commands for tools that are not present. Match the existing code style by hand.

## Architecture

Request flow: `Client` → `Transporter` → APITube REST API → typed response objects.

- `src/Client.php` — public entry point. Methods:
  - `news($endpoint, $params, $version)` — `everything` | `top-headlines` | `story` | `article` | `raw` (**POST**; `story` requires `id`)
  - `count($params, $version)` — **POST**, returns `int`
  - `suggest($type, $prefix, $version)` — `categories` | `topics` | `industries` | `entities` (GET)
  - `people/companies/sources/journalists($params, $version)` — list, return `ReferenceList` (GET)
  - `person/company/source/journalist($id, $params, $version)` — single profile, return `array` (GET)
  - `balance()` → `BalanceResponse` (GET), `ping()` → `bool`
- `src/Transporter.php` — HTTP layer. `get()`, `post()`, `getRaw()`. Sends header
  `X-API-Key`, `Accept: application/json`. Maps 401 → `AuthenticationException`,
  429 → `RateLimitException`, other non-2xx → `ApiException`.
- `src/Responses/` — `ArticleList`, `Article`, `ReferenceList`, `BalanceResponse`; each has a `fromArray()` factory.
- `src/DataObjects/` — value models nested inside articles (`Source`, `Author`, `Sentiment`, `Topic`, ...).
- `src/Exceptions/` — `ApiException` (base), `AuthenticationException`, `RateLimitException`.
- `src/ValueObjects/` — `ApiKey`, `BaseUri` (validate primitives at construction).

`examples/` mirrors each public method with a runnable script (reads `APITUBE_API_KEY` from env).

## Code style

- `declare(strict_types=1);` at the top of every file.
- Namespace `APITube\{Module}` (PSR-4, `src/`); tests under `APITube\Tests\` (`tests/`).
- 4-space indentation. Full type hints on params, return types and properties.
- Constructor property promotion with `readonly` where applicable; named arguments at call sites.
- PHPDoc on public methods (`@param` / `@return` / `@throws`).

## Do not

- Do not edit `vendor/` — it is generated by Composer.
- Do not bump `version` in `composer.json` by hand; releases drive the Packagist webhook (`.github/workflows/packagist.yml`).
- Do not hardcode or commit API keys; use the `APITUBE_API_KEY` env var (see `examples/`).
- Do not add a hard dependency on a specific HTTP client — keep PSR-18 discovery intact.
